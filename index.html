Architecture · role-based agent workflow

CUSTOMER + SALESPERSON
Counteroffer, priority, human initiative
↓
AGENT 1 · COORDINATOR
Interpret → plan → delegate → consolidate
↓
AGENT 2 · DEAL STRATEGY
Construct and context-rank packages
AGENT 3 · COMMUNICATION
Explain context and verified offers / draft exception
↓
DETERMINISTIC VALIDATOR (NOT AN AGENT)
Combined concession · trade cap · minimum gross margin
↓
PASS → SALESPERSON
Choose and present; customer decides
FAIL → MANAGER
Approve / reject exception; audit decision

Conceptual handoff: Agent 2's proposals are validated and ranked using explicit customer and inventory rules before Agent 3's customer-facing text is released. This diagram shows the intended architecture; browser prototype implements simulated roles, not LLM inference.

What this prototype demonstrates — and does not

Implemented:

Agent-role coordination, customer-priority and inventory-aware package ranking, candidate package generation, deterministic margin and limit checks, role-specific explanations, manager escalation, and an audit trail.

Not implemented:

Live LLM reasoning, authenticated dealership access, real market valuation, live inventory integration, financing calculations, user login/authorization, customer outcome measurement, or production-grade financial accounting.

Illustrative gross margin formula: replacement price − dealer cost − new-car discount + estimated trade resale − reconditioning − trade allowance. The trade allowance is treated as a vehicle acquisition cost. This simplified model is a classroom design assumption, not an industry-standard accounting specification.

Evidence basis: Group 2 Assignment 1 (two dealership interviews; AI-generated stakeholder simulation treated as hypotheses). The delegated negotiation envelope is a design proposal, not a verified existing dealership practice.
